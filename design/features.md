# Features

What Vertical Docs does, in the words of someone who uses it. One line per feature, grouped by who benefits. A built line ends with its proof: a number, a test or a command. A planned line names its phase in the [plan](architecture.md).

Every phase updates this list. Write nothing here that a tool result has not shown.

## For readers

- **Fast pages** (built). Lighthouse scores 100 for performance, accessibility, best practices and SEO, and CI fails a change that drops below 100, or below 95 for performance. Proof: five pages scored 100 in all four categories in each of three runs (local run on the phase 2 build, 2026-11-17); the scores CI enforces are in `lighthouserc.json`. On real content: five pages of the vAPI docs and five of the Vertical Studio docs, among them the longest page and the page with the most screenshots, scored 100 in all four categories in each of three runs, with a layout shift of 0 (local run on the phase 3a build, 2026-11-17). With the canonical URL, the share tags, the structured data and `robots.txt` of phase 3b, five pages of the vAPI docs again scored 100 in all four categories in each of three runs (local run, 2026-11-17).
- **Tiny downloads** (built). A page loads 2.5 KB of CSS and 1.2 KB of JavaScript, gzipped. A build over the budget of 4 KB and 1.25 KB fails. Proof: `scripts/check-dist.ts` and its tests; 2,479 and 1,208 bytes measured on the phase 3b build, 2026-11-17 (the CSS grew by 26 bytes with the longer font addresses). The JavaScript budget was 1 KB until the copy buttons.
- **Search that opens the right section** (built). Press `/`, `⌘K` or `Ctrl+K`, type a word, and the result opens the page at the heading that matched, also for a word that appears only under a small heading. Proof: the test "a word that appears only in an h3 section finds that section first" in `src/core/search.test.ts`; in Chrome, typing `indented` gave one result and opened `/reference/markdown/#a-part-of-a-section` (2026-11-17).
- **Search forgives typing** (built). The first letters of a word are enough, and a small typing mistake still finds the word. Proof: the test "finds a word from its first letters and through a typing mistake".
- **Search costs nothing until it is used** (built). A page downloads no search code. The first time search opens, the browser fetches 6.1 KB of search code, gzipped, and the index. Proof: the request log of the built site shows the search worker and `search.json` only after the first open (2026-11-17); a build with more than 8 KB of on-demand JavaScript fails.
- **Search works from the keyboard** (built). `Enter` opens the first result, `Tab` moves through the others, `Esc` closes, and a Close button serves phones. Proof: driven with key presses in Chrome, 2026-11-17.
- **Search speaks to screen readers** (built). The input is labelled and the number of results is a status message. Proof: the status element holds "9 results" after a query in Chrome (2026-11-17); not tested with a screen reader.
- **The best page first** (built). A page with the word in its title leads, and one page cannot fill the list on its title alone. Proof: the test "a section does not outrank other pages on the title of its page alone".
- **Works without JavaScript** (built). Every page is complete static HTML, and the sidebar groups open and close without a script. JavaScript only switches the theme, opens the search, copies, and scrolls the sidebar to the current page. Proof: the page text is in the files in `dist/`; the only scripts are the three inline ones `check-dist` measures.
- **Light and dark theme** (built). The theme follows the system and remembers a choice, with no flash on load. Proof: phase 1 screenshots in both themes; the saved choice is applied by an inline script before the first paint.
- **Readable code blocks** (built). Every code colour passes the 4.5:1 contrast minimum in both themes. Proof: measured in phase 1.
- **Mobile navigation with no JavaScript** (built). The sidebar opens with the Popover API. Proof: phase 1.
- **A sidebar that holds a hundred pages** (built; Safari not tested). A folder is a group that opens and closes; the groups around the current page are open and the sidebar scrolls to that page, on a phone when the menu opens. Proof: the vAPI docs, 109 pages three levels deep, show 16 entries with every group closed, and the Vertical Studio docs, 47 pages four levels deep, show 9; on the deepest page the current entry is in view in a window 800 and 640 pixels high and on a 375 by 667 phone (measured in Chrome, 2026-11-17); in Firefox 161 the groups open and close and the current entry is in view, also in the phone menu; the same in WebKit 26.6, the engine of Safari (2026-11-18).
- **Copy page and copy code** (built; Safari not tested). "Copy page" beside the title puts the page on the clipboard as Markdown, and every code block has a Copy button. Adding the buttons moves nothing on the page, and a reader without JavaScript sees no button that cannot work. Proof: in Chrome the clipboard held the 19,218 characters of `/reference/http-api/agents-and-router.md` and then the text of the first code block; no code block moved on any of the 109 vAPI pages at 1280 and 390 pixels wide (2026-11-17); Firefox 161 copied the same page and code block, and so did WebKit 26.6 (2026-11-18); a button that scrolls under the header stays behind it in Chrome, Firefox 161 and WebKit 26.6 (2026-11-18); with scripts off in Chrome the page holds one copy button and it is not displayed.
- **Images that do not move the page** (built). An image has its width and height in the page, loads when the reader comes near it, never grows wider than the text, and a PNG or JPEG is served as WebP. Proof: the 19 screenshots of the Vertical Studio docs are 12.2 MB as PNG and 1.6 MB as built; Lighthouse reports a layout shift of 0 on the page with the most screenshots, in three runs (2026-11-17).
- **Diagrams that follow the theme** (built; Safari not tested). A diagram drawn for light and for dark shows the right file, also after the manual theme switch. Proof: screenshots of the vAPI Agents page in both themes and after the switch; the request log shows the dark file is fetched only when the theme turns dark (Chrome, 2026-11-17); Firefox 161 and WebKit 26.6 show the right file for a light system, a dark system and after the switch.
- **Wide tables stay inside the page** (built). A table wider than the text scrolls sideways inside itself on every screen size, a small table keeps the full width of the text, and a long address or path breaks. The Tab key reaches a table, and the arrow keys then scroll it. Proof: at 1280, 1024, 900, 640 and 390 pixels wide, none of the 109 vAPI pages (205 tables) is wider than the window, and none of the 47 Vertical Studio pages (49 tables) at 1280, 900 and 390; before the change one vAPI page measured 1,337 pixels in a 1280 window and seven pages were wider than a 900 window (Chrome, 2026-11-18). Firefox 161 shows the same on the two pages with the widest tables at 1280 and 900 pixels. Lighthouse scored 100 in all four categories on seven vAPI pages, among them those two, in each of three runs (local run, 2026-11-18). On the vAPI Agents and Router page at 900 pixels, Tab reaches the first table that scrolls and the right arrow scrolls it to its end, in Chromium 153 and WebKit 26.6; WebKit shows no page wider than the window on the two pages with the widest tables at 1280, 900 and 390 pixels; Chromium's accessibility tree lists the table with its rows, column headers and cells (2026-11-18). Not tested with a screen reader.
- **A page for an address that has none** (built; not deployed). A dead link answers with status 404 and a "Page not found" page that keeps the header, the search and the list of pages. Proof: on the local Workers runtime `/no/such/page/` answered 404 with that page, also for a request with `Accept: text/markdown` (2026-11-18); `content/reference/worker.md` quotes the command.
- **Active section in the table of contents** (built, Chrome only). CSS marks the section being read; Safari and Firefox show a plain list. Proof: tested in Chrome 157, Safari 26.2 and Firefox 151 on 2026-11-17.

## For writers

- **Plain Markdown** (built). One file is one page, one folder is one sidebar group, and a page has three frontmatter fields. Proof: the pages in `content/`.
- **Mistakes stop the build** (built). A broken link or anchor, a search result that opens nothing, a wrong heading level, a `###` with no `##` above it, a code block without a language, HTML in a page, a task list, an image without alt text, from a web address, in a file that is not an image or written in a way the Markdown copy cannot follow, a field over its limit or a folder without an index page fails `pnpm check` with a message that says what to change. Proof: the tests in `scripts/check-dist.test.ts`, `src/core/writing.test.ts` and `src/core/nav.test.ts`.
- **Images in plain Markdown** (built). A writer saves the file beside the page and writes one Markdown line; a diagram per theme is two files named `-light` and `-dark`. Proof: `content/add-an-image.md` shows both on this site.
- **Docs can live in another folder or repository** (built). `DOCS_ROOT` points every command at another content folder. Proof: the vAPI docs (109 pages, 34 images) and the Vertical Studio docs (47 pages, 19 images), each in a folder outside the project, pass `pnpm check` (2026-11-17); `content/reference/configuration.md` says how.
- **Docs that update themselves from code changes** (written, not run; phase 3b). A product repository calls `docs-sync.yml` on a push to `main`: an agent without a shell edits the docs, a second job without the model key or a write token runs `pnpm check`, and a third refuses any change outside the content folder and keeps one pull request on `docs/sync`. Shown so far: the shell steps ran in a throwaway repository, where a docs change that waited in the pull request stayed in the patch, a file the agent wrote outside the content folder was left out, and the guard refused a patch with a file outside the content folder and a patch with a symlink (2026-11-17). Runs go one at a time, so two code changes close together cannot overwrite each other's docs (a concurrency group with `queue: max`, read in GitHub's documentation), and a run stops when it cannot ask GitHub whether docs changes are waiting. Not shown: a run on GitHub, which needs a demo repository and a model key.

## For agents

- **A Markdown copy of every page** (built). `/<page>.md` returns the page as Markdown with its title, and an image in it points at the full address of the file the site serves. Each page links to its copy at the end of the page and in a `link rel="alternate"` element. Proof: `curl http://localhost:4321/reference.md`, quoted in `content/reference/agents.md`; all 36 image links in the 109 Markdown copies of the vAPI docs are full addresses of files in the build (phase 3b build, 2026-11-17), and all 19 in the Vertical Studio docs were files in the phase 3a build; the tests "points each image outside code at the URL the site serves it at" and "throws for an image of the page that it cannot find in the Markdown".
- **`llms.txt`** (built). One file lists every page with its description, grouped like the sidebar, linking the Markdown copies by their full address. Proof: `curl http://localhost:4321/llms.txt`, and the test "writes llms.txt in sidebar order, one section per folder, linking the Markdown copies by their full address" in `src/core/llms.test.ts`.
- **`search.json`** (built). Every section of every page as `{ url, title, heading, text }` in one static file, usable with `curl` and `jq`. Every URL in it is checked on each build. Proof: 53 records for 11 pages, 7.2 KB gzipped (2026-11-17); the test "fails for a search result that points to no page or to no heading". At real size: 703 records for the 109 vAPI pages, 141 KB gzipped, and ten results 44 to 66 ms after the search opens (scripted key press and query, local server, desktop Chrome, three runs).
- **The same search in a terminal** (built). `pnpm run search "<query>"` prints the sections the site shows, in the same order, as plain text or JSON, for the last build or for a deployed site. Proof: the query `sidebar` gave the same nine URLs in the same order in the dialog and in the terminal (2026-11-17); the tests in `src/cli.test.ts`.
- **An MCP server** (built; not deployed). `/mcp` on the Worker has two tools: `search_docs` returns the sections the site search shows, in the same order, and `get_page` returns the Markdown copy of a page. The server keeps nothing between calls. Proof: the tests in `src/worker.test.ts`; on the local Workers runtime with the vAPI docs, Claude Code and Codex each searched for "hosted mcp", got the same three URLs as `pnpm run search`, and fetched the first page (2026-11-17). `content/reference/worker.md` quotes a call.
- **Markdown for `Accept: text/markdown`** (built; not deployed). A page URL answers a request with that header with the Markdown copy of the page. Proof: the test "answers Accept: text/markdown on a page URL with the bytes of its Markdown copy"; on the local Workers runtime all 109 pages of the vAPI docs returned the same bytes as their `.md` file (2026-11-17).

## For the team that runs it

- **Brand in three steps** (built). A site sets its name, one accent colour, and its logo and favicon. The accent is adjusted per theme so it stays readable. Proof: phase 1, same result in Chrome, Safari and Firefox.
- **A site keeps its own files** (built). A docs site is one folder outside the kit: `content/`, `docs.config.json` and `public/` with its logo, favicon and share image. `DOCS_ROOT` points every command at it, and nothing of the kit's own brand reaches the build. Proof: the vAPI docs built from their own folder with the name "vAPI", the accent `#ff7300` and their own logo and favicon in the page, and `pnpm check` exited 0 (2026-11-17).
- **Docs inside a product's own repository** (preview and build built; not published; `check`, `search` and `init` are planned in phase 5). A product installs Vertical Docs as one package and holds only its docs folder: `content/`, `docs.config.json` and `public/`. `vertical-docs dev` shows that folder as a live site and `vertical-docs build` writes the site to `docs/dist`; a folder other than `docs` is an argument. Proof: the tests "build writes the site of the product's docs folder to its dist" and "build takes the docs folder as an argument" in `src/cli.test.ts`; from a tarball of the kit installed in an empty folder, with npm and with pnpm, `build` wrote the 110 pages of the vAPI docs and `dev` answered 200 with the title "Introduction · vAPI", then showed an edit to a page and to `docs.config.json` within 3 seconds; `npx` with the tarball built the 48 pages of the Vertical Studio docs in a folder with no `package.json`; stopping the command with a signal stopped the preview (2026-11-18). Not tested on Windows.
- **One command decides done** (built). `pnpm check` runs types, lint, unused code, tests, the build and the checks on the build. Proof: `package.json`; CI runs the same command.
- **Small and fixed dependency list** (built). Five packages at run time and five for development, checked on every build. The fifth, `@modelcontextprotocol/server`, came with the MCP server. Proof: the test "fails for a dependency that is not on the list".
- **Hosting on Cloudflare Workers** (Worker built; not deployed). One Worker serves the built site, the Markdown answers and `/mcp`. Proof: the vAPI docs ran on the local Workers runtime (`wrangler dev`, 2026-11-17); a dry run of the deploy read 400 files and bundled the Worker at 150 KiB gzipped. Not shown: a deploy, which waits for a Cloudflare account.
- **Search-engine extras** (built). Every page names its canonical URL, a share image and its trail of sidebar groups as structured data; the site has `sitemap.xml` and `robots.txt`. All use `url` from `docs.config.json`. Proof: the tests in `src/core/seo.test.ts`; the sitemap of the vAPI docs lists 109 of 109 pages, and three sampled pages carry the canonical URL and the share tags (2026-11-17); a build without `public/share.png` fails.
- **Old addresses keep working** (built; not deployed). A site that moves lists its old paths in `public/_redirects`, and a line that points to no page or is not permanent fails the build. Proof: the test "fails for a redirect that points to no page, or that is not permanent"; on the local Workers runtime all 90 old paths of the vAPI docs answered 301 to a page that answered 200 (2026-11-17). Not shown: the same on Cloudflare.
- **A name and a mark** (built). The product is Vertical Docs, short name `vdocs`. Its mark is an open book standing up, which is also the V of Vertical: one shape in the header, in the browser tab in both themes, and on the share image of 1,200 by 630 pixels. Proof: `public/logo.svg`, `public/favicon.svg` and `public/share.png`; the header in the screenshot on `content/add-an-image.md` (2026-11-18).
